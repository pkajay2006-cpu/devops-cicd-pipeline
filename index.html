Academic & Engineering Context

Project Overview

Bridging the gap between software development and production operations through intelligent automation.

The Problem

Traditional Manual Deployments

In conventional college and legacy industry projects, code deployment is slow, manual, and error-prone:

  • Manual FTP / SSH: Code files manually transferred to servers over insecure connections.
  • Untested Code in Production: Developers skip unit tests under time pressure, leading to crashes.
  • "Works On My Machine": Software functions on the developer's laptop but breaks on the host server.
  • High Downtime & Fatigue: Deployment requires late-night releases and manual rollbacks.
The Solution

Automated CI/CD Pipeline

Our GitHub-based automated pipeline provides guaranteed code quality and zero-touch continuous deployment:

  • Instant Automated Verification: Every commit triggers a headless test suite running in an isolated runner.
  • Deterministic Environments: Built on Ubuntu Linux containers ensuring identical runtime configurations.
  • Strict Quality Gates: Production deployment is physically blocked if any test fails.
  • Zero-Downtime Delivery: GitHub Pages publishes verified code in under a minute without manual intervention.
DevOps Fundamentals

What is DevOps?

A cultural philosophy, collaborative practice, and toolchain designed to deliver software at high velocity with rock-solid reliability.

The word DevOps is a compound of Development (Dev) and Operations (Ops). Historically, developers wrote software without knowing how it would run, while operations teams managed servers without understanding the code. This created an adversarial "wall of confusion".

DevOps removes this barrier. By adopting automated pipelines, shared version control, continuous testing, and automated deployments, teams can build, test, and release reliable software rapidly and repeatedly.

Phase 1: Code Verification

Continuous Integration (CI)

Ensuring every proposed change is automatically tested and verified before it can enter the production codebase.

How CI Functions in this Project

Continuous Integration prevents "integration hell" by continuously validating small, incremental code commits. In this repository, whenever a developer runs git push origin main or creates a Pull Request:

  1. Event Trigger: GitHub detects the push event via native internal webhooks.
  2. Runner Provisioning: GitHub Actions allocates a fresh, isolated ubuntu-latest virtual machine.
  3. Checkout Code: The repository files are retrieved using actions/checkout@v4.
  4. Node.js Setup: The target runtime is configured using actions/setup-node@v4 with dependency caching.
  5. Automated Test Execution: The test suite (npm test) executes HTML, CSS, JavaScript, and Workflow schema tests.
  6. Quality Gate: If any test fails, the workflow immediately terminates and flags the commit with a red cross (❌), blocking deployment.

Security & Zero-Credential Publishing

This pipeline uses GitHub Actions OpenID Connect (OIDC) with GitHub-provided permissions (pages: write, id-token: write, contents: read). No private keys, SSH passwords, or personal access tokens are stored in the repository.

GitHub Configuration

GitHub Pages Setup Guide

To activate automated deployment on your personal GitHub account, follow these 3 steps:

  1. Navigate to your repository on GitHub.com.
  2. Click on Settings > Pages (in the left sidebar).
  3. Under Build and deployment > Source, select GitHub Actions (do NOT select "Deploy from a branch").
  4. Push this project to main. GitHub Actions will automatically test and deploy your site!
